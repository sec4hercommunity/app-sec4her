## Il filo

<Filo>Il web è uno scambio di messaggi. Oggi ci mettiamo in mezzo.</Filo>

<ScambioMessaggi
  da="TU (il browser)"
  in_mezzo="IL PROXY (chi legge le lettere che passano)"
  a="IL SITO (il server)"
  andata="la tua richiesta"
  ritorno="la risposta"
/>

Un **proxy** è come un postino curioso: ogni lettera che parte dal tuo browser passa prima da lui. Lui la può **leggere**, **fermare** e perfino **modificare** prima di consegnarla.

## Missione: entra come admin

<SimulatoreProxy
  sito="Biblioteca Bug (sito finto)"
  utenteDemo={{ username: "giulia", password: "libri2026" }}
  passi={[
    { id: "intercept", istruzione: "1. Attiva l'intercettazione (Intercept ON)." },
    { id: "login", istruzione: "2. Fai login nel sito con giulia / libri2026." },
    { id: "leggi", istruzione: "3. La richiesta è ferma nel proxy. Clicca su metodo, URL, header e body per capire cosa sono." },
    { id: "inoltra", istruzione: "4. Premi Forward e guarda la risposta: status 200, sei dentro come 'user'." },
    { id: "modifica", istruzione: "5. Rifai il login, ma prima di inoltrare cambia nel body role=user in role=admin." },
    { id: "flag", istruzione: "6. Inoltra di nuovo: nella risposta trovi la flag. Copiala qui sotto!" }
  ]}
  richiesta={`POST /login HTTP/1.1
Host: biblioteca-bug.sec4her.lab
User-Agent: Mozilla/5.0
Content-Type: application/x-www-form-urlencoded
Cookie: session=7f3a9c

username=giulia&password=libri2026&role=user`}
  rispostaUser={`HTTP/1.1 200 OK
Content-Type: text/html
Set-Cookie: session=7f3a9c; HttpOnly

<h1>Ciao giulia! Ecco i tuoi libri.</h1>`}
  rispostaAdmin={`HTTP/1.1 200 OK
Content-Type: text/html
Set-Cookie: session=7f3a9c; HttpOnly

<h1>Pannello ADMIN</h1>
<p>sec4her{ho_cambiato_la_lettera}</p>`}
  rispostaErrore={`HTTP/1.1 401 Unauthorized

<h1>Username o password errati</h1>`}
/>

<LatoHacker importante>
Cosa è successo? Il sito si **fidava** di un valore che arrivava dal browser (`role=user`). Ma tutto quello che parte dal browser lo puoi cambiare. Regola d'oro: **mai fidarsi dell'input dell'utente**. Questo errore ha un nome che incontrerai nel modulo OWASP: *Broken Access Control*.
</LatoHacker>

<Domande titolo="Domande da farti (il ragionamento da pentester)">
- Quali valori nella richiesta posso cambiare io?
- Il server **controlla** davvero quei valori, o si fida?
- Cosa succede se cambio un valore in qualcosa che non dovrei avere?
- Come cambia lo **status code** quando sbaglio password?
</Domande>
